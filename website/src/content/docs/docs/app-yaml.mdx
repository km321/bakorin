One file describes the app, runtime, auth, entities, policies, webhooks, and mail. Bakorin validates it with a strict schema, so unknown keys are rejected with a readable error.

The top level keys are `app`, `runtime`, `auth`, `entities`, `webhooks`, and `mail`. At least one entity is required.

<Aside type="tip" title="Prefer forms?">
The [app.yaml builder](/builder/) lets you start from a starter, add entities, fields, relations, permissions, auth, and mail rules, and copy or download the result. It checks your config with the same schema and compiler the server runs at boot, and you can paste an existing app.yaml to edit it.
</Aside>

## A complete example

```yaml title="app.yaml"
app:
  name: my-app
runtime:
  dialect: sqlite          # or postgres
  sqlite:
    path: ./data/app.db
  postgres:
    url: ${DATABASE_URL}
  files:
    driver: local          # or s3
    path: ./data/uploads
    maxBytes: 10485760
    allowedMimeTypes: [image/png, image/jpeg, application/pdf, text/plain]
    signedUrlTtlSeconds: 900
  jwt:
    secret: ${JWT_SECRET}
  backups:
    interval: 24h
    retain: 14
    destination: ./data/backups
  webhooks:
    retainDays: 30
  cors:
    origins: ["http://localhost:4321"]
auth:
  entity: users
  adminRole: admin
entities:
  users:
    auth: true
    fields:
      email: { type: email, unique: true, required: true }
      password: { type: password, required: true }
      name: { type: text, required: true }
      role: { type: enum, values: [user, admin], default: user, writable: admin }
  tasks:
    fields:
      title: { type: text, required: true }
      done: { type: boolean, default: false }
      ownerId: { type: relation, to: users, required: true }
    indexes:
      - [ownerId, done]
    policies:
      read: [owner(ownerId), admin]
      create: authenticated
      update: owner(ownerId)
      delete: owner(ownerId)
webhooks:
  - entity: tasks
    events: [create, update, delete]
    url: ${WEBHOOK_URL}
    secret: ${WEBHOOK_SECRET}
    maxAttempts: 10
    timeoutMs: 10000
```

## Environment variables in app.yaml

Use `${NAME}` to read an environment variable, or `${NAME:-fallback}` to provide a default. A referenced variable that is missing and has no fallback stops startup with `missing environment variable NAME referenced from app.yaml`.

```yaml
alerts:
  email: ${ALERT_EMAIL:-ops@example.com}
```

Do not give `jwt.secret` a fallback. Leave `jwt.secret` out and set `JWT_SECRET` in the environment instead. `bakorin start` refuses placeholder secrets.

## app

| Key | Type | Notes |
|---|---|---|
| `name` | string | Required. Shown in the admin UI and email subjects |
| `version` | string | Optional |
| `description` | string | Optional |

## branding

Optional white label for the admin, `/docs`, and system emails. Leave it out to keep the default look. See [Branding and white label](/docs/branding/).

| Key | Type | Notes |
|---|---|---|
| `name` | string | Display name instead of "Bakorin". Defaults to `app.name` |
| `primaryColor` | hex color | Quoted, like `"#0f766e"`. Adjusted automatically if it fails WCAG AA contrast |
| `accentColor` | hex color | Focus rings. Defaults to `primaryColor` |
| `logo` | path | File in `branding/`: svg, png, jpg, jpeg, webp |
| `favicon` | path | File in `branding/`: svg, png, ico |

## runtime

| Key | Default | Notes |
|---|---|---|
| `dialect` | `sqlite` | `sqlite` or `postgres` |
| `host` | `0.0.0.0` | Listen address |
| `port` | `4371` | The `PORT` environment variable wins |
| `sqlite.path` | `./data/app.db` | Moves under `BAKORIN_DATA_DIR` when that is set |
| `postgres.url` | | Usually `${DATABASE_URL}` |
| `jwt.secret` | `JWT_SECRET` | Usually left out so `JWT_SECRET` is used. Required outside `bakorin dev`, 32 or more random characters |
| `jwt.accessTtlSeconds` | `900` | Access token lifetime (15 minutes) |
| `jwt.refreshTtlSeconds` | `2592000` | Refresh token lifetime (30 days) |
| `files.driver` | `local` | `local` or `s3`. A bucket in the environment switches to `s3` |
| `files.path` | `./data/uploads` | Local upload folder |
| `files.bucket`, `files.endpoint`, `files.accessKey`, `files.secretKey`, `files.region` | | S3 settings. Prefer environment variables |
| `files.pathStyle`, `files.virtualHostedStyle` | path style | S3 addressing style |
| `files.maxBytes` | `10485760` | 10 MiB upload limit |
| `files.allowedMimeTypes` | png, jpeg, webp, gif, pdf, plain text | `["*"]` allows any type |
| `files.signedUrlTtlSeconds` | `900` | Signed download URL lifetime |
| `files.rateLimit` | | Upload limit, for example `{ limit: 30, window: 1h, per: user }`. See [Rate limits](#rate-limits) |
| `backups.interval` | | For example `24h` or `7d`. Turns on scheduled backups |
| `backups.retain` | `14` | Snapshots to keep |
| `backups.destination` | `./data/backups` | Folder or `s3://bucket/prefix` |
| `webhooks.retainDays` | `30` | How long delivered outbox rows are kept (1 to 3650) |
| `mail.retainDays` | `30` | How long sent mail rows are kept (1 to 3650) |
| `alerts.email` | | Address or list. Alerts for failed deliveries and overdue backups. See [Monitoring](/docs/monitoring/#alerts) |
| `alerts.webhook` | | URL that receives alerts as JSON |
| `alerts.backupMaxAgeHours` | | Alert when there has been no backup for this long |
| `alerts.checkIntervalMinutes` | `15` | How often alerts are checked |
| `cors.origins` | | Allowed origins. `CORS_ORIGINS` overrides it |
| `trustProxy` | `false` | `true` or a hop count, or a list of proxy CIDRs. `TRUST_PROXY` overrides it. See [Client IP and proxies](/docs/configuration/#client-ip-and-proxies) |
| `hooks` | `./hooks.ts` | Path to the hooks module |

## auth

| Key | Default | Notes |
|---|---|---|
| `entity` | | The entity with `auth: true`, usually `users` |
| `identity` | `email` | Field used to sign in |
| `password` | `password` | Password field |
| `role` | `role` | Role field. Always admin writable |
| `adminRole` | `admin` | Role value that counts as admin |
| `requireVerifiedEmail` | `false` | Block login until the email is verified |
| `signup` | follows `create` policy | `open`, `invite`, or `closed`. See [Who can sign up](/docs/auth/#who-can-sign-up) |

When `requireVerifiedEmail` is on, Bakorin adds an `emailVerified` boolean to the auth entity if the schema does not define one.

## entities

Each key under `entities` is an entity name. Names must start with a letter or underscore and contain only letters, digits, and underscores (64 characters max). `auth`, `audit`, `backups`, `docs`, `files`, `mail`, `status`, `webhooks`, and `_meta` are reserved because Bakorin serves built in routes at those paths under `/api/v1`.

| Key | Notes |
|---|---|
| `label`, `plural` | Human names for the admin UI |
| `display` | Field used as the row label in tables and relation pickers. Falls back to `name`, `title`, `email`, `company`, then `id`. Cannot be a secret field |
| `description` | Shown in the admin UI and OpenAPI |
| `auth` | Marks the auth entity |
| `renameFrom` | Previous entity name. Renames the table and keeps its rows. See [Schema changes](/docs/migrations/) |
| `fields` | Map of field name to a type or a field object |
| `indexes` | List of field names or arrays of field names |
| `policies` | `read`, `create`, `update`, `delete`. See [Permissions](/docs/permissions/) |
| `rateLimit` | Optional request limits per action. See [Rate limits](#rate-limits) |

Every entity gets three system fields you cannot redefine: `id`, `createdAt`, and `updatedAt`.

### Field types

`text`, `email`, `password`, `number`, `integer`, `boolean`, `date`, `datetime`, `enum`, `file`, `relation`.

A field can be a bare type (`title: text`) or an object:

| Flag | Notes |
|---|---|
| `type` | Required |
| `required` | Fields with a `default` are required unless you set `required: false` |
| `unique` | Unique index |
| `index` | Single field index |
| `default` | Default value |
| `values` | Enum values (required for `enum`) |
| `to` | Target entity (required for `relation`) |
| `onDelete` | `restrict` (default), `cascade`, or `set_null` |
| `writable` | `admin` or `none` |
| `adminOnly` | Same as `writable: admin` |
| `readonly` | Same as `writable: none` |
| `secret` | Hidden from API responses and webhook payloads. `password` fields are always secret |
| `private` | Returned only to the row's own user and to admins. On by default for the auth entity's identity, role, and `emailVerified` fields |
| `description` | Help text in the admin UI and OpenAPI |
| `renameFrom` | Rename a column without losing data |

### Write locks

- `writable: admin` (or `adminOnly: true`): only an admin may set the field. A non admin write that includes it returns **403**.
- `writable: none` (or `readonly: true`): nobody may set it through the generic CRUD API. Including it returns **403**.
- The auth `role` field is always `writable: admin`, even when you leave the flag out.

### Relations

```yaml
tasks:
  fields:
    leadId: { type: relation, to: leads, onDelete: set_null }
    ownerId: { type: relation, to: users, required: true, onDelete: cascade }
```

Relation fields store the related row's `id`, are indexed automatically, and become a database foreign key with the `onDelete` action when the table is created. See [Data and relations](/docs/data/) for `expand` and filtering.

<Aside type="tip" title="Many to many">
There is no built in many to many type. Model it with a join entity that has two relations.
</Aside>

### Rate limits

`rateLimit` caps requests per action. Limits are counted in the database, so they hold across restarts and instances.

```yaml
leads:
  policies:
    create: public
  rateLimit:
    create: { limit: 5, window: 10m }            # per client IP
    update: { limit: 60, window: 1m, per: user }
```

| Key | Notes |
|---|---|
| `limit` | Requests allowed per window (1 to 1000000) |
| `window` | `30s`, `10m`, `1h`, `1d`, or a number of seconds. 7 days at most |
| `per` | `ip` (default) counts per client IP. `user` counts per signed in user and falls back to the IP when signed out |

Over the limit, the API answers 429 with `{"error":{"code":"rate_limited"}}` and a `Retry-After` header set to the window length. Behind a proxy, set `TRUST_PROXY` so each visitor has their own IP (see [Client IP and proxies](/docs/configuration/#client-ip-and-proxies)). `runtime.files.rateLimit` takes the same `limit`, `window`, and `per` keys for uploads. To stop bots on public forms, pair a limit with a [verify hook](/docs/hooks/#captcha-and-bot-checks).

### Indexes

```yaml
indexes:
  - status
  - [ownerId, status]
```

The migrator runs `create index if not exists`. `index: true` on a field still works.

## mail

Transactional email rules. Templates live in the project's `mail/` folder.

```yaml
mail:
  - name: receipt
    entity: orders
    events: [create]
    to: "{{ record.email }}"
    subject: "Your receipt for order {{ record.number }}"
    template: receipt          # mail/receipt.html
    expand: [customer]
```

| Key | Default | Notes |
|---|---|---|
| `name` | `mail_<n>` | Id shown in the admin |
| `entity` | | Entity whose writes trigger the rule |
| `events` | | Any of `create`, `update`, `delete` |
| `to`, `cc`, `bcc` | | Address or list, each can be a template |
| `replyTo` | | One address |
| `subject` | `mail/<template>.subject` | Subject template |
| `template` | | File name in `mail/` |
| `when` | | Field conditions: a value, or `in`, `notIn`, `not`, `exists` |
| `changed` | | Update rules only: fire when one of these fields changed |
| `expand` | | Relation fields exposed as `expand.<field>` (secret fields stripped) |
| `maxAttempts` | `8` | 1 to 100 |

See [Email](/docs/email/#transactional-email).

## Schema changes

When `app.yaml` changes, Bakorin plans the migration in four groups:

- **Additive:** add an entity, an optional or defaulted field, an index, or an enum value. Applied automatically.
- **Renames:** `renameFrom` on a field or an entity. Applied after an automatic backup; data is kept.
- **Removals:** removed fields, entities, or enum values. Refused until you confirm with `bakorin migrate --allow-destructive <code>` or `BAKORIN_ALLOW_DESTRUCTIVE`. The data stays in the database.
- **Blocked:** type changes, required without a default, unique on an existing column. Stop the reload (or startup) instead of guessing.

`bakorin migrate --plan` shows the plan. See [Schema changes](/docs/migrations/).
