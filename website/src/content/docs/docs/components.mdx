`@bakorin/sdk` ships ready made pieces for the common parts of an app: auth screens, a user menu, gated content, a data table, forms built from your schema, file upload, and a live list. Each one comes in three layers, so you can take as much or as little as you want.

| Layer | Import | Use it when |
|---|---|---|
| [Headless helpers](/docs/headless/) | `@bakorin/sdk/headless` | You want the state and logic with your own markup, in any framework |
| [React components](/docs/components-react/) | `@bakorin/sdk/react` | You build with Next.js or another React app |
| [Astro components](/docs/components-astro/) | `@bakorin/sdk/astro/*.astro` | You build with Astro. They render on the server and work without JavaScript |
| [Styles](/docs/components-styling/) | `@bakorin/sdk/styles.css` | You want the default look, themed from your `branding` section |

Every browser call goes through the pass through route on your own site (`/api/bakorin`), so sessions stay in httpOnly cookies and tokens never reach JavaScript.

## What is included

- **Sign in form**: Email and password, with field and server errors. React: `SignInForm`. Astro: `SignInForm.astro`.
- **Sign up form**: Asks for what the auth entity lets people set. React: `SignUpForm`. Astro: `SignUpForm.astro`.
- **Forgot and reset password**: The reset email flow. React: `ForgotPasswordForm`, `ResetPasswordForm`. Astro: `ForgotPasswordForm.astro`, `ResetPasswordForm.astro`.
- **User menu**: Shows the signed in user with links and sign out, or a sign in link. React: `UserMenu`, `AuthButton`. Astro: `UserMenu.astro`, `AuthButton.astro`.
- **Gate**: Shows content only to signed in users, optionally with a role. React: `Gate`. Astro: `Gate.astro`.
- **Data table**: Pagination, sortable columns, toggles, delete, and live updates. React: `DataTable`, `Pager`. Astro: `DataTable.astro`.
- **Record form**: Create and edit forms built from the schema. React: `RecordForm`. Astro: `RecordForm.astro`.
- **File upload**: Drag and drop or pick a file, with progress and size and type checks. React: `FileUpload`. Astro: `FileUpload.astro`.
- **Live list**: A list that updates as records change in any tab. React: `LiveList`. Astro: `LiveList.astro`.

## Accessibility

The components aim for WCAG 2.2 AA, and the starters are checked with axe in CI.

- Every input has a visible label. Required fields are marked, and hints and errors are tied to the input with `aria-describedby`.
- Invalid fields get `aria-invalid`, and focus moves to the first one on submit. Form level errors use an alert region.
- Tables have a caption (it can be visually hidden), sortable headers are buttons with `aria-sort`, and the page status is announced.
- The user menu is a disclosure button that closes on Escape and returns focus.
- Focus rings are always visible, and the default colors meet 4.5:1 for text in light and dark mode.

## Try them

Both starters use the components for sign in, a protected dashboard, and a tasks page with create, toggle, delete, and live updates. From a checkout of the repository:

```bash
bun run create my-app --frontend astro --schema todo --yes
bun run create my-app --frontend next --schema todo --yes
```
