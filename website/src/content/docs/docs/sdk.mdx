`@bakorin/sdk` is a small fetch based client. It handles auth calls, token refresh, and typed CRUD for your entities.

Install it from the npm `beta` tag with `bun add @bakorin/sdk@beta` (or `npm install @bakorin/sdk@beta`). Projects scaffolded by `create-bakorin` already include it. `--sdk local` still links the checkout copy when you run the CLI from a source clone.


## Create a client

```ts
import { createClient } from "@bakorin/sdk";
import type { BakorinEntities } from "./bakorin.gen.ts";

const api = createClient<BakorinEntities>({
  baseUrl: "http://127.0.0.1:4371",
  getAccessToken: () => localStorage.getItem("access"),
  getRefreshToken: () => localStorage.getItem("refresh"),
  setTokens: (tokens) => {
    localStorage.setItem("access", tokens.accessToken);
    localStorage.setItem("refresh", tokens.refreshToken);
  },
});
```

| Option | Notes |
|---|---|
| `baseUrl` | Bakorin API origin |
| `getAccessToken`, `getRefreshToken` | Return the stored tokens (sync or async) |
| `setTokens` | Called after login, accept invite, and refresh. Signup never returns tokens |
| `fetch` | Optional custom fetch |

On a 401, the client calls `/api/v1/auth/refresh` once and retries. Refresh is mutexed, so parallel 401s share one rotation.

For server rendered apps, use the [Astro](/docs/astro/) or [Next.js](/docs/nextjs/) helpers, which keep tokens in httpOnly cookies.

## Auth methods

```ts
await api.signup({ email: "you@studio.test", password: "password123", name: "You" });
// signup answers { ok, status: "check_email", requiresVerification, message } and never signs in
await api.login({ email: "you@studio.test", password: "password123" });
const me = await api.me();
await api.logout(refreshToken);

await api.forgotPassword({ email: "you@studio.test" });
await api.resetPassword({ token, password: "new-password-1" });
await api.verifyEmail({ token });
await api.resendVerification({ email: "you@studio.test" });

await api.invite({ email: "new@studio.test", role: "user" }); // admin only
await api.acceptInvite({ token, password: "password123", name: "You" });
```

## Entities

```ts
const tasks = api.entity("tasks");

const page = await tasks.list({
  filter: { done: false, dueOn: { op: "lte", value: "2026-12-01" } },
  sort: "-createdAt",
  limit: 20,
  expand: "leadId",
});
// page.data, page.meta.total

const task = await tasks.get(id, "leadId");
const created = await tasks.create({ title: "Send proposal" });
await tasks.update(created.id, { done: true });
await tasks.delete(created.id);
```

Errors throw an `Error` with the server's message.

Many to many fields take and return arrays of ids. Filter them with `has`, which matches records linked to any of the given ids:

```ts
await api.entity("projects").list({ filter: { tagIds: { op: "has", value: [designId, urgentId] } } });
```

## Files

```ts
const file = await api.files.upload(input.files[0]); // { id, filename, contentType, size, url, downloadUrl, expiresAt }
await api.entity("projects").update(projectId, { brief: file.id });

const project = await api.entity("projects").get(projectId, "brief");
project.$expand.brief?.url;          // signed link: images, PDF and text open inline
project.$expand.brief?.downloadUrl;  // the same file as a download

const fresh = await api.files.sign(file.id); // a new link for a file you uploaded
```

Store the file id in the record, never the link: links expire after `signedUrlTtlSeconds`. `expand` works on list calls too. The SDK returns full URLs on your `baseUrl`, or on the pass through route in the browser client. See [Files](/docs/files/#show-a-file).

## Realtime

```ts
const stop = api.subscribe("tasks", (change) => {
  // change.eventId, change.entity, change.op ("create" | "update" | "delete"), change.id, change.record
}, {
  onReset: () => refetch(),        // missed too much, reload
  onStatus: (status) => {},        // "connecting" | "open" | "reconnecting" | "closed"
  onError: (error) => {},          // 400, 401 after a failed refresh, 403, or 404: no retry
});
stop();
api.closeRealtime(); // close the shared stream
```

All subscriptions on a client share one stream, which reconnects with backoff and resumes from the last event. See [Realtime](/docs/realtime/).

## Browser client

`createBrowserClient()` from `@bakorin/sdk/browser` talks to the pass through route on your own site (`/api/bakorin` by default), so the session stays in httpOnly cookies. Set it up with the [Astro](/docs/astro/#browser-calls-and-live-updates) or [Next.js](/docs/nextjs/#browser-calls-and-live-updates) route. Options: `basePath`, `origin`, and `fetch`.

## Generated types

`bakorin typegen` writes `bakorin.gen.ts`. Pass its entity map to `createClient`, `createAstroClient`, or `createNextClient` for typed `entity()` names and records.

The output also includes `bakorinSchema`, which the [components](/docs/components/) and [headless helpers](/docs/headless/) use to build forms and tables.

## Components and helpers

| Import | What it has |
|---|---|
| `@bakorin/sdk/headless` | Auth state, collections with optimistic writes, live lists, uploads, and forms. See [Headless helpers](/docs/headless/) |
| `@bakorin/sdk/react` | React components and hooks. See [React components](/docs/components-react/) |
| `@bakorin/sdk/astro/*.astro` | Astro components. See [Astro components](/docs/components-astro/) |
| `@bakorin/sdk/styles.css` | Default styles. See [Styling components](/docs/components-styling/) |

Each import is its own entry, so a page only loads what it uses.

## Rich text

The server cleans `richtext` fields before it stores them. Render them with the SDK helpers, which clean the HTML again with the same allowlist, so HTML that reached the page some other way is still safe.

Astro:

```astro
---
import RichText from "@bakorin/sdk/astro/RichText.astro";
---
<RichText html={post.body} as="article" class="post-body" />
```

Next.js and React (works in Server Components):

```tsx
import { RichText } from "@bakorin/sdk/react";

<RichText html={post.body} as="article" className="post-body" />
```

For your own markup, `sanitizeRichText(html)` returns clean HTML and `richTextToPlain(html, maxLength)` returns the text for excerpts. Both come from `@bakorin/sdk/astro`, `@bakorin/sdk/next`, `@bakorin/sdk/headless`, and `@bakorin/sdk/richtext`. The `.bk-richtext` class in `@bakorin/sdk/styles.css` keeps images inside their container and styles quotes and code blocks.

`RecordForm` shows `json` fields as a monospace text area that must hold valid JSON, and `richtext` fields as a text area of HTML. The server cleans that HTML like any other write.

## Errors

Failed calls throw `BakorinRequestError` with `status`, `code`, and, for a bad value, the `field` it belongs to.
