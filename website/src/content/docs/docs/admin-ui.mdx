Every project serves an admin UI at `/admin/`. It is built from your `app.yaml`, embedded in the binary, and needs no extra setup.

<Image src={listDark} alt="Bakorin admin in dark mode showing a Leads table with company, contact, email, status, notes, and owner columns" />

## Sign in and first admin

On a fresh project the admin shows **Create your first admin**. After that it is a normal sign in screen.

<Image src={signin} alt="Bakorin admin sign in screen in light mode" />

## Admins only

The admin UI is only for users whose role matches `auth.adminRole` (default `admin`).

After sign in, the admin UI asks the server whether the session is an admin before it shows anything. A user without the admin role sees an **Admins only** screen with their email and a **Sign out** button. The sidebar, tables, and project pages are not rendered for them. If an admin loses the role while signed in, the next schema refresh sends them to the same screen.

<Image src={adminsOnly} alt="Admins only screen telling sam@studio.test the account is not an admin, with a Sign out button" />

The real enforcement is on the server. These endpoints return 401 when signed out and 403 for non-admins:

- `GET /api/v1/_meta`
- `GET` and `POST /api/v1/backups`
- `GET /api/v1/audit`
- `GET /api/v1/webhooks`, `GET /api/v1/webhooks/deliveries`, and the retry and test routes
- `GET /api/v1/mail`, `POST /api/v1/mail/preview`, `POST /api/v1/mail/test`, `GET /api/v1/mail/deliveries`, and the retry route
- `POST /api/v1/auth/invites`

Regular users still use your front end and the entity API, where your [policies](/docs/permissions/) decide what they can read and write.

## Themes

A **System, Light, Dark** switch sits in the top bar. System follows your operating system. The choice is saved in the browser.

## Data

Each entity appears under **Data** in the sidebar.

- Tables are sortable and searchable, with pagination.
- Relation columns show the related row's `display` field instead of a raw id.
- **New** and **Edit** open a side drawer with a field for each column, using each field's `description` as help text. Enums become selects, relations become searchable pickers, and `file` fields become file pickers.
- Deletes ask for confirmation.
- On the auth entity, **Invite user** sends an invite email, and unverified users get a **Resend verification** action.

## Project pages

| Page | What it does |
|---|---|
| **Backups** | Lists snapshots and takes a live backup (`POST /api/v1/backups`). Restore stays CLI only |
| **Schema** | Draws your entities and relations. See [Schema visualizer](/docs/schema/) |
| **Webhooks** | Lists configured webhooks and deliveries, filters by status, retries failed rows, sends a test event |
| **Mail** | Lists mail rules and templates, previews a template against sample data or a real record in a sandboxed frame, sends a test to you, and shows the delivery log with Retry. See [Email](/docs/email/#admin-mail-page) |
| **Audit** | The append only audit log: signups, logins, failed logins, resets, invites, role changes, admin writes, backups |
| **API docs** | Opens the bundled Swagger UI at `/docs` |
